    32→    32→## Policy enforced by this run
    33→    33→
    34→    34→- DRY RUN ONLY — this tool performs ZERO database writes: it has no insert/update/delete code path and reads the existing records with a single GET using the public publishable key.
    35→    35→- Existing-record matches are reported for human review; nothing is merged, updated or created.
    36→    36→- Every coordinate in the input is a CANDIDATE until independently confirmed against the exact business; directory pins are never treated as confirmed GPS evidence.
    37→    37→- coordinates_verified can never be set from a third-party directory listing; the tool rejects unsupported verification claims outright.
    38→    38→- Missing coordinates, phone numbers, opening hours, prices, photos and menu data stay NULL — the tool never invents values.
    39→    39→- External listing ratings (listing_rating + source_url) are kept strictly separate from Foodie community reviews (review_count / community_rating), which are trigger-maintained in the database and rejected if present in an import.
    40→    40→- Recommended initial verification_status for any future import is 'unverified'; 'verified' can only be granted by human review.
    41→    41→- A Google Maps listing URL (maps_listing_url) documents the listing only — it never verifies a coordinate, and a search-results URL is flagged because it identifies no business.
    42→    42→- External rating/review counts (listing_rating, listing_review_count) require a source and a check date (rating_checked_on); they stay strictly separate from Foodie community reviews.
    43→    43→- review_decision records the human duplicate-review decision verbatim — it never overrides the tool's matching and never triggers a database action.
    44→    44→- Reports are deterministic (no timestamps): same input + same baseline snapshot ⇒ byte-identical report (idempotent re-runs).
